## [0.3.2] - 2026-11-13
### Fixed (Real Linux 6.6 Kernel, XDP/bpftool & Live Chutney Tor 0.4.9.11 Verification)
- **Microdesc Consensus `r` line parsing (`src/consensus_index.py`):** Supported 8-token `/var/lib/tor/cached-microdesc-consensus` router lines (which omit the descriptor digest token and store the relay IP at `parts[5]` rather than `parts[6]`), preventing real Tor `0.4.x` relays from silently dropping all consensus entries and exposing peer relays.
- **UAPI-safe `--emit-xdp-c` compilation & `FIN`/`RST` socket teardown (`src/shield_engine.py`):** Replaced undefined kernel-internal `struct frag_hdr` with self-contained `struct ipv6_frag_hdr_min` (with non-first fragment skip) and added `-I/usr/include/$(uname -m)-linux-gnu` to compile hints so `clang -target bpf` compiles cleanly and passes the Linux `6.6` BPF verifier; allowed token-bucket-bounded `FIN`/`RST` (`!syn`) teardown packets for banned flooders in both XDP (`blocked_v4/6`) and `nftables` (`tor_fin4/6`) so disconnected flooders release kernel `ESTABLISHED` sockets cleanly and trigger hysteresis `NORMAL` recovery.
- **Kernel `CONFIG_NFT_CONNLIMIT` fallback, `/usr/sbin` path resolution & active-ban preservation (`src/shield_engine.py`, `src/relaysentry.py`):** Added `kernel_supports_nft_connlimit()` + `--no-nft-connlimit` so `--emit-nft-consensus` and `--enforce-shield --shield-backend nft` do not fail transactionally on kernels lacking `nft_connlimit`, resolved `/usr/sbin/{nft,bpftool}` when `$PATH` omits `sbin`, and re-injected unexpired `active_bans` with remaining TTL when `nft` table re-sync runs during an active wave.

## [0.3.1] - 2026-11-13
### Fixed (Goldfish Code & Hostile Audit Remediations)
- **Per-IP nftables rate-limiting & kernel `--allow-cidr` parity (`src/shield_engine.py`):** Replaced global rule-level `limit rate over` (which could exhaust across distinct honest 1-socket Tor users on busy relays) with per-IP `flags dynamic, timeout` sets (`tor_syn4`/`tor_syn6`, `timeout 60s`), added `timeout 120s` eviction to `connlimit4`/`connlimit6`, embedded `allow_net4`/`allow_net6` (`flags interval`, including `127.0.0.0/8`, `::1/128`, and `--allow-cidr`) directly into `generate_nft_consensus_sync()`, made `table inet relaysentry_shield` idempotent (`add`/`delete table`) across `--ban-ttl` changes, and flushed `tor_ddos4`/`tor_ddos6` cleanly upon recovery to `NORMAL`.
- **Self-contained `--emit-nft-hints` (`src/shield_engine.py`):** Emits standalone `table inet relaysentry_hints` commands without assuming pre-existing `inet raw`/`inet filter` tables or breaking `ct state new` with `notrack`.
- **XDP `bpftool` `ENOENT` deadlock & RSS amplification (`src/shield_engine.py`):** Switched `syn_bucket_v4`/`syn_bucket_v6` from per-CPU to global `BPF_MAP_TYPE_LRU_HASH`, added a bounded 4-header IPv6 extension-header walker before `IPPROTO_TCP`, allowed `/32` & `/128` `--allow-cidr` hosts into XDP allowlists, and recovered gracefully when `bpftool batch` encounters `ENOENT` on LRU-evicted `map delete` keys.
- **`--watch` Consensus refresh, `--offline` guardrail & privacy masking (`src/relaysentry.py`, `src/correlator.py`):** Refreshes Onionoo Consensus periodically during multi-day `--watch` runs via `ShieldController.update_consensus()`, refuses live `--enforce-shield` when Consensus is empty under `--offline`, keeps flooder IPs masked in `--enforce-shield --shield-dry-run` output unless `--reveal-flooders` is passed, and requires `>= 3` raw samples under `1-in-16` stride sampling before revealing/banning.
- **Procfs `TIME_WAIT` filtering & parser hardening (`src/telemetry_procfs.py`, `src/telemetry_tor.py`, `src/consensus_index.py`):** Excludes `TIME_WAIT` and closing TCP states before IP allocation, adds a `64 MiB` byte bound on live procfs reads, recovers from corrupt local cache files when online, and guards float-to-int overflows (`1e400`) in `MetricsPort` parsing.

## [0.3.0] - 2026-11-13
### Added
- `BEGIN_DIR` Thunderstorm telemetry & correlation (`src/telemetry_tor.py`, `src/correlator.py`): parses `tor_relay_dos_total{type="begindir_rate_rejected"|"begindir_rejected"|"begindir_hsdir_rejected"|"circuit_rejected"|"circuit_killed_max_cell"|"circuit_killed_max_cell_outq"|"conn_rejected"|"concurrent_conn_rejected"}` and `tor_relay_streams_total{cmd="BEGIN_DIR"}` deltas (`THUNDERSTORM_BEGIN_DIR_FLOOD`, `TOR_CIRCUIT_CELL_DOS_TRIGGERS`).
- Post-`0.4.9.16` half-open `BEGIN_DIR` bypass & event-loop stall detection (`HALF_OPEN_BEGIN_DIR_BYPASS_SUSPECTED`): flags heavy relay kernel socket queue buildup when `begindir_*_rejected == 0` OR when `MetricsPort` times out under CPU saturation (with `ControlPort` timeouts reported cleanly via `CONTROL_PORT_UNRESPONSIVE`).
- Non-crashing telemetry resilience (`--metrics-timeout`, default `5.0s`): `--watch` loop catches transient `MetricsPort`/`ControlPort` timeouts, HTTP read aborts, and closed-socket EOF errors cleanly (`METRICS_PORT_UNRESPONSIVE` / `CONTROL_PORT_UNRESPONSIVE`) while preserving previous MetricsPort counter baselines.
- Dual-stack consensus-safe `nftables` generator (`--emit-nft-consensus`): outputs atomic `known_relays4`/`known_relays6` allowlists (protecting Directory Authorities & peers) plus timeout `tor_ddos4`/`tor_ddos6` rate-limit sets, paired with kernel `sk_buff` bloat mitigation guidance (`sysctl -w net.core.high_order_alloc_disable=1`, `DoSBeginDirRateEnabled 1`, `DoSBeginDirLimitEnabled 1`, `NumCPUs 16`, `MaxMemInQueues 2 GB`, emergency `DirCache 0`).
- Built-in adaptive enforcement controller (`ShieldController` via `--enforce-shield`, `--shield-backend {auto,nft,xdp}`, `--shield-dry-run`, `--ban-ttl`, `--bpf-pin-dir`, `--allow-cidr`) and `bpftool batch file -` XDP map emitter (`--emit-xdp-sync`) driving `allow_relay_v4/6` and `blocked_v4/6` (or `nft -f -` `known_relays4/6` + `tor_ddos4/6`) with strict consensus/honest-client/allowlist exemptions and automatic hysteresis de-escalation cleanup.
- 4-stage local Thunderstorm & half-open bypass simulator (`test/simulate_thunderstorm.py`) and 10-suite regression verification (`[TEST 9]` & `[TEST 10]`) in `test/verify_relaysentry.py`.
